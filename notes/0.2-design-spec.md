# 0.2 UX design spec — WS3 (visual design pass)

Status: **for review** — no code lands from this doc until the maintainer
approves it. Scope: tokens, spacing rhythm, motion, states (empty/loading/
error/offline), and the concrete deficiencies found in `crates/app-gpui`.
Constraint: this is a **polish, not a rebrand** — the sumi-e palettes, the
no-card-box feed, the dots-not-badges rule, and the "ensō is the only
animation" philosophy all stay (DESIGN.md §1.3, §5, D23).

Sources: current `crates/app-gpui/src/theme.rs` + `views/*.rs`;
retired webapp (`git show a4b09e8:public/styles.css`, `src/render/*`,
`src/theme.ts`); `notes/0.2-research.md` §3–4 (Dark Wisp findings).

---

## 1. Design tokens

### 1.1 Color — keep, formalize roles

`theme.rs`'s ten-token `Palette` is right and stays byte-identical. What's
missing is not new colors but **role discipline**: several views reach for raw
colors where a role should exist. Add four *derived* role helpers (computed
from the existing palette, no new colors):

| Role | Definition | Where it's used today (inconsistently) |
|---|---|---|
| `hairline_strong` | `hairline()` at 100% | separators inside cards vs. borders around panels |
| `hover_wash` | `ink()` @ 5% alpha (§5.1's convention, never a helper) | hover backgrounds are hand-rolled `hover(|s| s.opacity(0.72))` in feed.rs:1070,1081,1091,1109,1169,1186,1197 — seven copies of one idea |
| `ink_faint` | `muted()` @ ~65% | whispers, placeholder-grade text — currently some rows use `muted` + `.opacity(0.6)` ad hoc (content.rs:863) |
| `pressable` | rest = `muted()` + underline; hover = `vermilion()` | D23's one-link-token rule; audit every clickable text against it |

Rules to codify (already mostly honored, make them law):
- **Vermilion is a seal, not a theme**: primary action, active state, ensō,
  engaged glyphs, quote-embed left rule. Never body text, never backgrounds
  larger than a pill.
- **Links are ink-colored + underlined** at rest (§5.1). Grep-check
  `text_color(rgb(theme::vermilion()))` callsites — the "Load new notes" pill
  (feed.rs:1293) is correct (a seal moment); anything decorative is not.
- Error text uses `err()`, never vermilion; the login doors' amber-vs-red
  split (D26) is the pattern to generalize (§4 below).

### 1.2 Spacing — one scale, eight steps

Today's spacing is gpui's default `p_N` ladder used freely: `gap_1` (18×),
`gap_2` (71×), `gap_3` (9×), `gap_4` (7×), `py_0p5`…`py_4`, `px_2`…`px_4`,
plus a long tail of raw `px(n)` calls. It works visually because the default
ladder *is* a 4px scale — but nothing names it, so ad-hoc values leak
(`px(16.0)` in composer.rs:870, `px(5.)`-style nudges, etc.).

Proposed scale (constants in theme.rs; 4px base, one irregular pair):

```
S0 = 0   S1 = 2   S2 = 4   S3 = 8   S4 = 12   S5 = 16   S6 = 20   S7 = 32
```

Assignment rules:
- Card/row internal gap: **S3 (8px)** — matches today's `gap_2` (gpui `2` = 8px). Keep.
- Feed card vertical padding: **S4 (12px)** per side — today's `py_4` = 16px
  top+bottom each is *loose*; the webapp used `padding: 14px 4px`
  (styles.css:221 `.notif-row`). Proposal: `py_3`-equivalent (12px), letting
  the whitespace-between-cards carry the rhythm, which is the no-card-box
  design's whole point (feed.rs:972).
- Horizontal page gutter: **S5 (16px)** — today's `px_4`, keep.
- Reading column: `COL_W = 640` (content.rs:24) — the webapp's was 720px
  (`#app { max-width: 720px }`, styles.css:100). At 12–13.5px desktop type,
  640 is right; **keep 640 and cite it** as a deliberate divergence from the
  webapp, so it stops looking like a typo.
- Inline-control padding (buttons, pills, inputs): `S2–S3` horizontal,
  `S1–S2` vertical. No more freehand.

### 1.3 Type scale — collapse five sizes to four

Current usage across views (grep): **15.0 / 14.0 / 13.5 / 13.0 / 12.5 / 12.0
/ 11.5 / 11.0 px** — eight sizes, with `12.0`/`12.`/`12.5` all live and
`text_size(px(13.0))` (45×) and `px(12.0)` (41×) nearly tied. That's not a
scale, it's sediment. Collapse to:

| Token | px | Role | Current examples |
|---|---|---|---|
| `T_BODY` | 14 | note bodies, author names (feed.rs:993) | 14.0 / 13.5 |
| `T_UI` | 13 | timestamps, meta rows, list secondary, settings labels | 13.0 / 12.5 |
| `T_SMALL` | 12 | whispers, glyphs labels, badges, rail tooltips | 12.0 / 11.5 |
| `T_READER` | 15 + `line_height(1.35)` | reader/article body only (reader.rs:202,251) | 15.0 |
| display serif | C059, 17–20 | reader h1, empty-state quotes | — |

Rules: body line-height `relative(1.2)` (content.rs:406,425) for feed text;
`1.35` reserved for the reader's long-form. Kill 11.0 and 11.5 entirely —
at gpui's unhinted grayscale AA (theme.rs:114–121) anything under 12px goes
mushy; that's a *measured* constraint, not taste.

### 1.4 Radii — adopt the §5.1 ladder

Current: `.rounded(px(4.))` (16×), `.rounded_sm` (13×), `.rounded_full`
(12×), `px(3.)` (8×), `px(6.)` (3×). DESIGN.md §5.1 already specifies a
ladder that the code doesn't follow: **inputs 8 / media 10 / cards 12 /
modals 14 / pills 999**. Reconcile honestly: the desktop feed has no card
boxes (sumi-e), so "cards" is rare; the *actual* boxed things are embeds,
pills, media, inputs. Proposed ladder in theme.rs:

```
R_EMBED = 6    // quote embeds, code chips (absorbs today's 3/4/6)
R_INPUT = 8    // text inputs, buttons, suggestion popovers
R_MEDIA = 10   // images, video tiles, lightbox thumbs
R_PILL  = full // dots, pills, avatars
```

One rule worth keeping from the current code: anything under 4px is a
mistake at hairline borders — the `px(3.)` chips read as accidental.

### 1.5 Hairlines & strokes

Hairline 1px `border_color(hairline())` is correct and consistent; keep.
Formalize one exception already in the wild: the caught-up seal's short
hairline (D23) and quote-embed's left rule (vermilion, D23) are the only two
"expressive" strokes allowed.

## 2. Layout rhythm

### 2.1 Note card anatomy (feed.rs:916–…)

Lock the anatomy as spec, so WS4 edits don't drift:

```
│ gutter px_4 (16)                                        │
│ [avatar 28] Name(SEMIBOLD, T_BODY)      time(T_UI, mut)  │  head row, gap S3
│ ↳ reply whisper (T_SMALL, muted, 1 line max)             │  optional
│ body (T_BODY, lh 1.2, pre-wrap)                          │
│ [media row] [quote embed] [rich card]                    │  optional, R_MEDIA/R_EMBED
│ [action row: reply · boost · bookmark · zap glyphs]      │  dim @ rest, ink on hover
│ ─ between cards: 8px gap + nothing (no rule, no box)     │
```

Deviations to fix: cards currently use `gap_2` (8px) between *all* sections
including head→body (feed.rs:978); body should sit **tighter to the head**
(4px) than media sits to body (8px) — one exception in the helper, not
per-call nudges.

### 2.2 Lists

- Feed rows: no separators, whitespace only (feed.rs:972) — **keep**; this is
  the identity. Whitespace budget = S4 (12px) pad + S4 between.
- Notifications/search/thread rows: same anatomy, denser (`py_1` = 4px) —
  these are scans, not reads.
- Settings panes: grouped panels on `panel()`, `R_INPUT` radius, hairline
  border, `p_4` inside — one `settings_group()` helper instead of per-pane
  boxes.

### 2.3 Panes

Rail (left) + reading column (640, centered) + nothing else. Overlay panes
(composer, lightbox) get `R_INPUT` + hairline + a `panel()` surface at 100%
opacity — no translucency anywhere (sumi-e paper is opaque).

## 3. Motion

The philosophy holds: **the ensō breathes; everything else is a state
change, not an animation** (§1.3 quiet-by-default; D23's hover-opacity
discipline). All existing animation already honors
`desktop::reduced_motion()` (portal `prefers-reduced-motion`, desktop.rs:16–28)
— keep that as the single gate, read via `desktop::reduced_motion()` with no
`cx` (the D32 static-mirror pattern).

Motion inventory (complete; nothing may be added without a D-log entry):

| Motion | Duration | Where | Reduced-motion |
|---|---|---|---|
| Ensō breath (opacity 0.4→1.0) | 3.4s ease-in-out loop | login.rs:309–313 (waiting door) | static at full opacity (login.rs:304) |
| Video play-mark breath | ~1.4s loop, opacity 0.65±0.3 | content.rs:865–868 | static dim (content.rs:863) |
| Zap-in-flight bolt breath | ~1.4s loop, opacity 0.55±0.25 | feed.rs:1147–1156 | static dim (feed.rs:1156) |
| Hover transitions | opacity/color only, ≤150ms, **zero layout shift** (D23) | all pressables | still apply (hovers aren't motion) |
| Scrolls | instant, always | §1.3 | — |

Explicit non-goals: no card-entrance fades (the webapp's inkfade was a
web-idiom and the GTK port already dropped it), no toast slide-ins, no nav
transitions. A state appears; it does not travel.

## 4. States — defined once per class

Every list surface (feed, thread, profile, notifications, search, reader)
renders the same four state classes from one shared helper; only the copy
varies. Today each view hand-rolls its own, with drift.

### 4.1 Empty
- **Copy**: one quiet line + one serif whisper where the moment deserves it.
  Best-in-class already exists: notifications' "Nothing new. Sit quietly."
  (notifications.rs:525) and search's read-back "Nothing found for “{q}”."
  (search.rs:563). The feed's "Nothing here yet — the relays are still
  answering." (feed.rs:1325) is wrong for a *persistently* empty feed — the
  relays aren't "still" answering after minutes. Split feed-empty into:
  *first load still pending* (→ loading class) vs *loaded, zero events*
  ("Quiet here. The relays remember nothing from this view.")
- **Form**: centered, `T_UI`, `muted()`, generous `p_8`; no icon glyph, no
  illustration, no retry button inline (retry is §4.3's).

### 4.2 Loading
- Copy with a trailing ellipsis, muted: "connecting to the relays…"
  (feed.rs:186), "loading the thread…" (thread.rs:48), "Gathering…"
  (notifications.rs:106), "Searching…" (search.rs:140), "loading…"
  (profile.rs:122). Normalize casing + ellipsis via one helper; today
  notification's "Gathering…" capitalizes where none else do.
- **No spinners.** The absence of motion is the loading indicator; the
  ellipsis is enough. (Consistent with §3: only ensō breathes.)

### 4.3 Error
- Feed-level failure today overwrites the *status line* with
  `format!("… {e}")` (feed.rs:459, thread.rs:144, profile.rs:225,
  search.rs:219 "Search failed: {m}", notifications.rs:205) — raw error
  strings, mixed formats, and the leading `…` collides with the loading
  convention. Spec: errors render as a **dismissible inline strip** on
  `panel()` with `err()` text + a quiet Retry action; copy pattern:
  "<What failed> didn't answer." + the kind, not the debug string. Kind the
  copy like D22 kinds media: transient (relay down → "relays didn't answer —
  Retry") vs verdict (not found → no retry offered).
- Row-level failures (a single card's media) are silent and retried per the
  D22 backoff — never bubble to the pane strip.

### 4.4 Offline / degraded
- The Tor-mode warm-up indicator and "delivering…" outbox honesty state
  (research §3.4) are the two offline surfaces: both render as the same
  pill-shaped status on `warn()` amber — states, not errors (D26's split).
- One new quiet state for the shell rail: a single `live()` dot goes grey
  when the pool is fully disconnected. Nothing else moves.

## 5. Concrete deficiency list (audit, file:line)

Spacing / type / radii:
1. Eight text sizes live (15/14/13.5/13/12.5/12/11.5/11) with duplicates
   `px(12.0)`/`px(12.)`/`px(12.5)` — no scale. Collapsed in §1.3.
2. Radii drift: `.rounded(px(4.))` 16×, `.rounded_sm` 13×, `px(3.)` 8×,
   `px(6.)` 3× — ignores §5.1's ladder. → §1.4.
3. Seven hand-rolled hover-wash copies (feed.rs:1070,1081,1091,1109,1169,
   1186,1197) — one `hover_wash` helper. → §1.1.
4. Feed card vertical padding `py_4` (16px) is double the webapp's row
   rhythm (styles.css:221 uses 14px *total* row padding); head→body gap
   equals body→media gap — no hierarchy. → §2.1.
5. Raw `px(16.0)` magic number inline in composer.rs:870 instead of a token.

Empty states:
6. feed.rs:1325 copy is wrong for persistent emptiness ("still answering"
   never resolves) and the state isn't visually distinct from loading.
7. Reader/thread/profile empties: no dedicated empty row — they show
   `status` loading copy indefinitely or nothing; only feed/notifications/
   search have real empty states.

Error surfaces:
8. Five views overwrite the status line with raw error debug strings via
   `format!("… {e}")` (feed.rs:459, thread.rs:144, profile.rs:225,
   search.rs:219, notifications.rs:205): unkinded, unretryable, ellipsis
   collides with loading copy. → §4.3.
9. search.rs:569 ("Relays without NIP-50 search answer nothing.") is the
   only honest degradation note in the app; generalize that pattern to
   NIP-11-less relays and unknown-kind cards.

Loading / motion:
10. notifications.rs:106 "Gathering…" is the only capitalized loading line;
    normalize.
11. All three breathing animations gate reduced-motion correctly, but the
    gate is duplicated at each site (content.rs:854, feed.rs:1147) — fine,
    but any *fourth* animation must justify itself against "ensō breathes,
    everything else is a state change."
12. `input.rs:280` gates a motion path off reduced-motion — confirm it's
    covered by the §3 inventory (it is; listed for audit completeness).

Structure:
13. `COL_W = 640` (content.rs:24) vs webapp 720 (styles.css:100) — keep 640,
    record as deliberate (§1.2); otherwise it reads as drift.
14. Settings panes each hand-roll boxes; one `settings_group()` helper
    (§2.2) to stop radius/border drift before WS4 adds the relay-health pane
    (research quick-win 3).

## 6. Rollout order (WS4 quick wins absorb these)

1. **theme.rs tokens first** (spacing consts, 4-step type scale, radius
   ladder, hover_wash/ink_faint helpers). Everything else consumes them.
   Mechanical, grep-driven, low risk.
2. **States helper** (empty/loading/error strip/offline pill) + fix
   feed.rs:1325 copy + the five error surfaces (deficiency 8). Highest
   user-visible payoff per line.
3. **Feed card anatomy pass** (§2.1: padding, head→body gap) — one view,
   then **notifications**, then **search/thread/profile** adopt the same
   anatomy (profile's Notes tab is literally the Feed, D30, so it comes free).
4. **Settings group helper** — do it in the same WS as the relay-latency
   pane (research quick-win 3) so the new pane is born on-token.
5. **Reader last**: T_READER + serif display sizes; it's the most isolated
   view and the least likely to churn.

What WS4's already-planned quick wins absorb: the keyboard bindings and
shell-rail dot (research §5 items 1, 4) ride step 2's states work; the
relay-health pane rides step 4; the emoji typeahead and nsec tripwire touch
no visual tokens and proceed independently.

Guardrail for all of it: no new animation, no new color, vermilion stays a
seal, and the feed stays whitespace-composed.
